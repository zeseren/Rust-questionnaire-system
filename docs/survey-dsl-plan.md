## 文本语法契约（阶段 6）

文本是统一 AST 的另一种编辑方式。Rust 与 TypeScript 分别解析，之后均调用已有文档编译器；不执行脚本，不新增运行语义。

```text
dsl 1 semantics 1;
bind question age = "00000000-0000-4000-8000-000000000001";
bind variable adult = "00000000-0000-4000-8000-000000002001";
bind node intro = "00000000-0000-4000-8000-000000001001";
bind node finish = "00000000-0000-4000-8000-000000001002";
let adult: boolean = answer(age) >= 18;
validate age = answer(age) >= 0;
entry intro;
page intro [age] -> finish;
end finish = complete;
```

绑定集中在声明之前；别名是最多 64 个 ASCII 字符的标识符（字母或下划线开头），全文唯一，类别为 `question/option/variable/node`，必须显式绑定标准小写 UUID。别名不依赖题目标题或位置。复制仍由 AST 的身份映射负责，格式化文本重新生成绑定。变量用 `let name: boolean|number|text|choice|choices = expr;` 声明；题目规则为 `visible|required|validate question = expr;`，同题同类规则不可重复。

`page name [q1, q2] -> next;` 声明页面；`branch name { when expr -> target; else -> fallback; }` 声明有序分支，默认出口必须放在最后；`end name = complete|screen_out;` 声明终点。只要存在节点就必须且只能声明一个 `entry name;`，仍遵守前向拓扑和题目归属契约。

表达式支持布尔、JSON 字符串、保留原文的 JSON 数字；`answer(q)`、`answered(q)`、`selected(q,o)`、`contains_any(q,[o1,o2])`、`contains_all(q,[o1,o2])`、`variable(v)`、`all(...)`、`any(...)`、`coalesce(value,fallback)`、`length(value)`。变量也可直接写别名。中缀运算按 `||`、`&&`、`== != < <= > >=`、`+ -`、`* /`、前缀 `!` 的优先级从低到高结合，同级左结合；括号明确分组。负号仅用于数字常量，表达式取负可写 `0 - expr`。格式化对布尔列表使用函数形式，保持原 AST 分组和短路顺序。数字常量还可写 `number("原文")`，确保格式化往返保留词法表示。支持 `//` 行注释。

文本最多 1 MiB UTF-8、65536 个词元、64 层解析嵌套；生成 AST 继续遵守更严格的 16 层、单表达式 256 节点与文档总预算。语法及语义错误提供行、列、稳定分类；语义错误保留 AST 路径并定位到对应声明。编辑中的错误文本不替换当前规则模型，应用成功后才参与草稿保存。

## 表达式契约（阶段 1）

表达式包为 `{ "dsl_version": 1, "semantics_version": 1, "expression": ... }`。两个版本均必须识别，不能忽略未知版本。阶段 1 只实现 JSON AST；阶段 6 的文本先转换成同一 AST，再通过原有编译入口。

版本按 u32 范围内的非负整数值检查，JSON 的 `1` 与 `1.0` 等价；布尔和数字字符串不是版本号。多处同时无效的输入不承诺诊断顺序，单处错误的分类与定位由共享样例约束。

节点使用 `op` 判别，拒绝未知字段。题目及选项引用为标准小写连字符 UUID，不使用标题或序号。编译时绑定题目类型和选项集合，得到不能由调用者随意构造的编译结果；执行前检查输入类型。完整问卷约束与适用性由后续文档/流程层处理。

配置身份与引用统一要求非零、小写连字符 UUID，覆盖题目、选项、变量、规则归属、流程入口/节点/出口/页面题目和文本绑定。Rust DTO 字段在反序列化边界拒绝非规范写法（HTTP 为 `400 invalid_json`），AST 引用在编译时拒绝；TypeScript 配置入口使用相同接受集。选项答案作为值规范化，仍接受大写、无连字符、花括号和 `urn:uuid:` 写法，不适用于配置 ID。共享回归逐个扰动配置字段，避免其他字段掩盖校验缺口。

文本空白按 Unicode `White_Space` 判定，与 Rust `str::trim` 一致。U+0085 多行文本仅含空白时为缺失，U+FEFF 是非空白内容；普通填写、流程填写、必填校验、省略空答案与进度判断共用规则，非空白答案不裁剪。数字输入框允许首尾空白，数字 AST 常量的原文不能带空白。对应样例见 [`input-contracts.json`](../fixtures/survey-logic/input-contracts.json)。

提交答案和改答事件的 `question_id` 同样使用严格 UUID 身份规则；宽松规范化仅适用于选项答案值。测试同时覆盖配置字段、答案题目身份、事件题目身份以及选项值，避免边界误用。

| 节点 | 字段 | 类型规则 |
| --- | --- | --- |
| `boolean` / `number` / `text` | `value` | 分别为布尔、数字原文字符串、文本 |
| `answer` / `answered` | `question_id` | 返回该题类型的值或缺失；`answered` 返回布尔 |
| `selected` | `question_id`, `option_id` | 单选或多选，选项必须属于该题 |
| `contains_any` / `contains_all` | `question_id`, `option_ids` | 多选，非空且无重复的选项集合 |
| `not` | `expression` | 布尔取反 |
| `all` / `any` | `expressions` | 非空布尔列表 |
| `compare` | `comparison`, `left`, `right` | `eq/ne` 支持同类型的布尔、数字、文本；`lt/le/gt/ge` 仅数字 |
| `coalesce` | `value`, `fallback` | 同类型；只有缺失时使用替代值 |
| `length` | `value` | 文本的 Unicode 标量个数或多选集合大小 |
| `arithmetic` | `operator`, `left`, `right` | 数字 `add/subtract/multiply/divide` |

选择类型只通过专用选择运算符判断，避免把选项 UUID 与普通文本混用。计算字段引用留到阶段 2，不能通过任意对象属性访问绕过类型检查。

阶段 2 增加 `{ "op": "variable", "variable_id": "变量 UUID" }`；变量必须在文档包中声明，不能冒充题目 ID。独立表达式入口没有变量声明环境时会拒绝该引用。

### 缺失与错误

运行值包括布尔、数字、文本、单选、多选及 `missing`。布尔位置的 `missing` 即 unknown。缺失来源包括无答案、明确 null 和被流程层排除的答案。空白文本、空多选的业务规范化由问卷层负责，原始错误输入不能默默变成缺失。

- `not unknown = unknown`。
- `false and unknown = false`，`true and unknown = unknown`。
- `true or unknown = true`，`false or unknown = unknown`。
- 普通比较、算术、长度、选择判断传播缺失。
- `answered` 仅判断规范化答案是否存在，`coalesce` 显式消除缺失。
- 布尔列表从左向右短路；编译器仍检查所有分支。运行错误不是 unknown；除零、溢出和输入类型错误必须返回结构化错误。
- 求值前统一检查所有被引用的上下文值。即使某个分支将被短路，无效上下文也不能通过；纯计算分支的运行错误只有执行到该分支时才触发。

### 数值、文本和资源界限

基础版沿用现有答案的有限 IEEE 754 binary64 数值语义，不承诺任意精度小数运算。数字常量以 JSON 字符串保留原文，按现有裸整数精度与 i64/u64 边界规则解析，防止浏览器先舍入。小数及指数按既有 f64 规则处理；正负零等价。比较为规范化数值的精确比较，不隐式添加容差；需要近似比较时由作者明确表达区间。算术每一步检查有限性，除零报错。

文本比较区分大小写、不自动 trim 或 Unicode 归一化；长度按 Unicode 标量计算。拒绝 NUL 及非 Unicode 标量输入。每个表达式最多 256 节点、最大深度 16（根为 1），文本常量最多 5000 标量，数字原文最多 64 字符（正指数补号后计）。每个选择集合最多 50 项。问卷级总规则预算在阶段 2 引入，不能把单表达式限制当成整个文档限制。

## 文档与执行语义（后续阶段约束）

1. `Document.logic` 可缺省且序列化省略；旧文档走原有单页行为，不能改变旧版幂等指纹。发布版本冻结规则与语义版本。未知版本拒绝执行。
2. 可见条件为 true 才显示；隐藏题不必填。基础 `required` 与动态条件做逻辑或，动态条件不能取消静态必填；unknown 的动态必填在最终校验时必须给出明确诊断。
3. 数据依赖图无环；流程图禁止任意回跳，所有节点有结构性出口。规则只能引用此前可获得的数据，汇合点引用某支独有答案必须显式处理缺失。显示规则不能依赖自身答案。
4. 页面只在 next 事件完成当前页校验后转换；按声明顺序选择第一个 true 分支。更高优先级条件 unknown 时阻止前进，不能落入默认分支。最后有默认出口。可检测的遮蔽/不可达规则给出诊断，不承诺证明任意表达式互斥。
5. answer_changed 事件在一次原子更新中重算依赖、可见性和路径；失去适用性的答案、错误与派生值清除。翻页不等于隐藏。仍适用的答案保留并重校验；返回已清理分支时从空答案开始。
6. previous 走当前有效历史；改答后裁剪失效历史。提交请求一旦进入不确定结果状态，冻结答案、版本和幂等键，重试相同载荷。
7. 服务端从入口按顺序执行，只让已校验且适用的答案进入上下文；不得先让路径外答案参与分支判断。到达 complete 仅代表可提交，事务成功后才是 submitted。
8. 整卷复制通过题目、选项、页面及变量的两遍 ID 映射重写引用；删除或改类型时报告影响，不静默放宽规则。
9. 统计以历史版本规则重算适用性，区分已答、适用未答、规则跳过。选项比例继续使用已答人数作分母。逻辑路径不等于实际浏览轨迹。旧版本 CSV 格式保持兼容。

## 阶段 2 契约与实施记录

2026-10-04 完成文档级编译。新增 `backend/src/logic_document.rs` 和 `frontend/src/document-logic.ts`，Rust 领域接口仍通过 `domain` 导出。`Document.logic` 缺省或 null 时序列化省略，不改变旧文档格式；草稿保存、复制校验会编译规则。

规则包包含必需的 `dsl_version`、`semantics_version`、`variables` 和 `rules` 四个字段，未知字段拒绝。变量条目包含稳定 `id`、声明 `value_type`、`expression`；规则条目包含目标 `question_id`，以及至少一个 `visible_if`、`required_if`、`validate` 布尔表达式。可选规则的 null 等价于缺省。一个题目不能重复声明规则，变量身份不能与题目、选项或其他变量冲突。

编译先绑定所有变量类型，再检查表达式与声明类型相符，最后进行确定性的拓扑排序：同一时刻就绪的变量取 UUID 最小者。变量不能有环。每个变量展开为传递的题目依赖集合，显示和必填规则必须只依赖严格前置题目；约束可以读取当前题，不能读取后续题。这也拒绝了通过多层变量隐藏的自引用和前向引用。删除变量、题目或选项，或重排题目导致引用失效时，保存明确失败，不自动清除规则。

文档最多 100 个变量、100 组题目规则；在单表达式 256 节点/16 层限制之外，全部表达式合计最多 4096 节点、262144 字节紧凑 UTF-8 JSON。变量计算结果按原生类型传给后续表达式，不转成答案 JSON 再解析。前端沿用现有无损 JSON 编解码，抽到独立 `json.ts` 供 HTTP 与纯文档复制共用；规范化的原生数字不再用显示字符串重新判断裸整数范围，避免把 `1e20` 误拒绝。

编译结果提供变量执行顺序，以及在规范化有效答案上下文上的变量值、规则表达式值。结果保留 unknown；尚不执行题目显隐、动态必填或最终提交校验，也不能据此认定访问路径。计算错误保留声明变量或题目规则的路径。

整卷复制两遍重写题目、选项、变量与规则目标引用。前端单题复制同步复制目标规则，保留外部依赖，重写直接的自身答案/选项引用；共享计算变量不克隆，仍指向原变量。复制不会改写文本常量中的 UUID 字符串。

## 阶段 3 流程与会话契约

2026-10-06 实现独立的 Rust 和 TypeScript 流程引擎。Rust 的 `flow.rs` 仍是私有模块，领域接口经 `domain` 导出；前端由 `flow-compiler.ts` 负责结构和数据可用性检查，`flow.ts` 负责会话。没有增加依赖、数据库表或浏览器页面。

### 流程定义

规则包增加可选 `flow`；缺省或 null 使用内存中的单页流程，不写回旧文档。`flow` 包含入口 `entry` 和拓扑顺序的 `nodes`，未知字段拒绝。节点采用以下三种封闭结构：

| 类型 | 字段 | 行为 |
| --- | --- | --- |
| `page` | `id, question_ids, next` | 顺序处理本页题目，next 事件成功后才离开 |
| `branch` | `id, branches, otherwise` | branches 是有序的 `{when, target}`；选择第一个 true，unknown 或计算错误阻止低优先级和默认出口 |
| `end` | `id, outcome` | outcome 为 `complete` 或 `screen_out`；不产生保存、提交或账号额度副作用 |

入口必须是第一个节点且为页面；所有边只能指向数组中的后续节点。页面、分支和结束节点的 UUID 不得与题目、选项、变量或其他节点重复。最多 256 个节点，每个分支含 1—16 个条件，必须有默认出口。每页至少放置一道题；按节点顺序拼接页面题目必须恰好等于文档题目数组，不能重复、遗漏或另行重排。规则造成全页隐藏时，next 会跳过该页。

编译检查目标存在、前向边和结构可达性；有限前向图且所有非终点有出口，保证任一路径最终到达结束节点。直接的永假布尔条件、直接的真条件遮蔽后续条件会报错；其他表达式的恒真、互斥及不可达性不做一般性证明。分支表达式计入阶段 2 的文档总节点数和字节预算。

### 合流与缺失值

编译器计算各节点必经的前置节点集合。分支只能读取此前页面的题目；显示/必填/约束继续遵循阶段 2 的题目先后顺序。即使包裹默认值，也不能引用未来题目。

在合流位置引用某条分支独有的答案，需要显式消除缺失。当前认可 `answered`、`coalesce`，以及从左到右的布尔短路保护，例如 `all(answered(q), compare(answer(q), ...))` 或 `any(not(answered(q)), ...)`。先读取再补检查不算保护。变量按拓扑顺序生成直接读取摘要，不反复展开变量 AST；间接引用同样接受检查。这是保守检查，不尝试推导任意表达式间的蕴含关系。

经过某页不代表其中每题都有答案；可选、隐藏或校验失败仍会产生 missing。运行时按题目顺序，只让适用且校验通过的规范化答案进入上下文。显示条件为 false 或 unknown 时隐藏；显示条件计算错误保留题目及错误，不能悄悄跳过。静态必填与动态必填取或，静态 true 会短路动态表达式；动态必填为 unknown 时阻止继续。空的可选答案不运行自定义约束；已填答案先加入当前题约束的临时上下文，通过后才供下游使用。

流程按实际读取计算变量，并在一次表达式求值中缓存共享依赖；布尔短路和 coalesce 不触发未执行到的计算变量。原有整包 `evaluate` 仍用于显式计算所有变量与规则的原始值，不用它推断填写路径。

### 会话与事件

`FlowSession` 绑定不可变文档，只允许通过事件修改状态。Rust 借用文档，TypeScript 复制文档；对外快照独立于内部状态。没有可信客户端历史的反序列化接口，也没有提交接口。

| 事件 | 输入 | 处理 |
| --- | --- | --- |
| `change` | `question_id, value` | 仅允许修改当前页的可见题；value 使用答案 JSON 类型，null 清空；从入口重算有效路径、答案和错误，原子清理不再适用的输入 |
| `next` | 无 | 当前页有错误则拒绝；否则前进到下一可见页面或终点，并加入实际访问历史 |
| `previous` | 无 | 弹出当前有效历史，返回上一实际访问页面；翻页本身不删除仍适用答案 |

无效输入保留在会话内部供后续改答，快照 `answers` 只含有效的规范化答案。改答清除隐藏和路径外输入及错误；仍适用的后续答案保留并重校验。再回到旧分支时，已清除的答案不会恢复。失败事件不修改状态。

快照包含 `current_node`、`outcome`、实际访问的 `history`、根据当前答案推导的 `path`、路径内 `visible` 题目、有效 `answers`、题目 `errors`、路径末端 `route_error`、最近一次改答的 `cleared`。预测路径不包含自动分支节点，可以提前出现终点，但 outcome 只有 next 真正到达终点后才出现。错误可能来自尚未访问的后续页面；next 只检查当前页，界面接入时需按当前页呈现。推导路径不是实际浏览轨迹。

旧文档的虚拟页面 ID 为全零 UUID，虚拟终点 ID 为 `00000000-0000-0000-0000-000000000001`，仅用于内存快照，不写入文档或版本指纹。整卷复制重写全部节点、出口、题目与表达式引用；前端单题复制同时将新题插入源题所属页面的紧邻位置。

### 阶段边界

流程文档可以保存、读取和复制。带 logic 的文档仍不能发布；服务端最终提交重建路径、报表适用性重算属于阶段 4，编辑器/预览/填写界面接入属于阶段 5。screen_out 只返回会话结果，持久化及账号额度策略仍待后续明确。

## 阶段 4 提交与报表契约及验证

2026-10-06 完成服务端闭环。Rust 从会话中分离 `FlowEvaluator`，让交互事件与最终答卷重建共用投影过程；同一报表只编译一次历史版本，再逐份重建。TypeScript 增加 `FlowSession.evaluateAnswers`，从给定最终输入计算同样的结果，不读取或改变会话当前输入和历史。两端读取新增的 `submissions.json`。

### 提交与发布

`Document.validate_answers` 对带 logic 的历史版本从入口重建最终路径；无 logic 的旧版本保持原有校验和规范化分支。请求仍只包含版本、幂等键与答案数组，不接受路径、访问历史或客户端适用性判断。输入先拒绝重复与外来身份，再按有效顺序校验；隐藏或未进入分支的答案即使为 null 也拒绝，不在服务器静默清理提交。未知条件、题目约束错误和筛选结束均不能产生答卷。

最终重建返回规范化 `answers`、全题目的 `question_states` 与推导 `path`；这不表示已经提交。`question_states` 使用 `answered`（已答）、`unanswered`（适用未答）、`skipped`（规则跳过）。只有已校验且适用的答案能参与后续变量和分支，路径外答案不能影响合流必填条件。

本阶段放开普通 complete 流程的服务端发布与提交。包含 screen_out 节点的文档仍不能发布，因为筛选结果的持久化和账号额度策略尚未确定；纯引擎继续支持筛选结束，正式提交不保存该结果。

提交事务、锁顺序、资格检查和成功重放顺序保持原样。幂等指纹仍为原有 `{version_id, answers}`，没有追加路径、状态或当前 DSL 元数据；成功重试使用请求绑定的不可变历史版本，仍能跨关闭和版本切换重放。校验失败不写入答卷，也不占用登录限次额度。

### 答卷、统计与 CSV

答卷详情增加 `question_states`，按该答卷的历史版本重算；无规则旧版本每题都适用。各题统计增加 `applicable_count`、`unanswered_count` 和 `skipped_count`，满足：

- `applicable_count = answered_count + unanswered_count`。
- `total_count = applicable_count + skipped_count`。
- 选择题比例继续使用 `answered_count` 作分母；跳过和未答都不进入数字均值，合法零值仍参与。

带 logic 的版本在每个 CSV 答案列后增加 `状态 [题目 UUID]` 列，值为“已答”“适用未答”“规则跳过”。答案缺失列仍为空，因此用户真的回答“规则跳过”也不会与状态混淆。无规则旧版本不增加列，保留原列顺序、数值表示与公式注入保护。

报表专用的存储重建入口不面向 HTTP。JSONB 会将指数展开成十进制，可能超出原始提交的 64 字符限制或裸整数范围；读取已规范化数字时先恢复有限 f64 的规范表示，再执行题型、规则和路径检查。HTTP 原始输入继续执行完整精度和字节限制。历史规则与保存答案不一致时返回内部错误，不伪造跳过状态或部分统计。

### 网页边界

报表页已展示适用、未答和跳过数量，详情展示每题状态。规则编辑器、分步预览与网页填写仍属阶段 5：本阶段为带 logic 的文档显示暂未开放提示，暂不允许从现有网页编辑器发布，避免旧版整页填写忽略规则；服务端接口可用于已接入流程的调用方。无规则问卷网页行为不变。

阶段 5 还需处理填写输入适配与提交冻结。规范化结果中的原生 number 用于计算；发送时需保留合法的数字传输表示，尤其不能把 `1e20` 直接序列化成超出 u64 的裸整数后提交。

### 文本 DSL

Rust `logic_text.rs` 和 TypeScript `logic-text.ts` 独立实现词法、带优先级的表达式解析、别名绑定及文档声明解析，最终都调用既有文档编译器。Rust API 经 `domain` 导出；没有新依赖、数据库迁移或文本 HTTP 端点。TypeScript 另提供格式化入口，生成确定性别名；往返保留 AST 身份、数字原文和表达式分组，自定义别名与注释不进入持久模型。

2026-10-08 更新：上述手写解析器是本阶段初次实现的记录。Rust 现已使用 `pest` / `pest_derive 2.9.2`，文法位于 `logic_text.pest`，优先级由 `PrattParser` 处理；仍先做资源预检、在 AST 构造时限制容量，并复用身份绑定和文档编译。TypeScript 实现与共享语义契约继续沿用；当前替换与验证结果见[后端 crate 评估](backend-crate-assessment.md)。

语法错误保留行列；语义错误保留 AST 路径，并定位对应声明。文本编辑与模型应用分开，未应用文本计入离开提醒并阻止保存，不会静默丢弃错误文本。解析深度与构造中的 AST 深度分别受限，长左结合中缀链在构造阶段即拒绝，避免 Rust 析构深树耗尽栈。
