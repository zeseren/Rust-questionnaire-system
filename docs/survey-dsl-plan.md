# 问卷 DSL 与流程引擎实施计划

日期：2026-10-04。实施分支：`feat/survey-dsl`。

## 目标与实施约束

用带类型的 JSON AST 描述问卷规则，以确定性扩展状态机执行页面流程。Rust 与 TypeScript 分别实现，读取同一份 JSON 语义样例；不采用 WASM。文本语法与可视化编辑最终生成同一种 AST。

按可验证的阶段推进，阶段完成后记录实际验证结果。表达式内核完成不代表跳题产品功能已经交付。基础版本只依赖不可变问卷和最终有效答案；随机、时间、外部查询、访问次数、任意回跳及持久填写会话不进入基础版本。

Rust 遵守 `F:\rust-skills\SKILL.md` 的相关规则，保持当前单成员 workspace、纯领域层和错误边界。使用借用、封闭枚举、编译后类型、明确的数值错误与严格反序列化。与既有要求冲突时，以用户和仓库约定为准：测试独立存放，不在业务 Rust 文件末尾放测试，不引入模拟、性能测试框架或不必要的依赖。

## 表达式契约（阶段 1）

表达式包为 `{ "dsl_version": 1, "semantics_version": 1, "expression": ... }`。两个版本均必须识别，不能忽略未知版本。当前只实现 JSON AST，文本不是可执行输入。

版本按 u32 范围内的非负整数值检查，JSON 的 `1` 与 `1.0` 等价；布尔和数字字符串不是版本号。多处同时无效的输入不承诺诊断顺序，单处错误的分类与定位由共享样例约束。

节点使用 `op` 判别，拒绝未知字段。题目及选项引用为标准小写连字符 UUID，不使用标题或序号。编译时绑定题目类型和选项集合，得到不能由调用者随意构造的编译结果；执行前检查输入类型。完整问卷约束与适用性由后续文档/流程层处理。

| 节点 | 字段 | 类型规则 |
| --- | --- | --- |
| `boolean` / `number` / `text` | `value` | 分别为布尔、数字原文字符串、文本 |
| `answer` / `answered` | `question_id` | 返回该题类型的值或缺失；`answered` 返回布尔 |
| `selected` | `question_id`, `option_id` | 单选或多选，选项必须属于该题 |
| `contains_any` / `contains_all` | `question_id`, `option_ids` | 多选，非空且无重复的选项集合 |
| `not` | `expression` | 布尔取反 |
| `all` / `any` | `expressions` | 非空布尔列表 |
| `compare` | `comparison`, `left`, `right` | `eq/ne` 支持同类型的布尔、数字、文本；`lt/le/gt/ge` 仅数字 |
| `coalesce` | `value`, `fallback` | 同类型；只有缺失时使用替代值 |
| `length` | `value` | 文本的 Unicode 标量个数或多选集合大小 |
| `arithmetic` | `operator`, `left`, `right` | 数字 `add/subtract/multiply/divide` |

选择类型只通过专用选择运算符判断，避免把选项 UUID 与普通文本混用。计算字段引用留到阶段 2，不能通过任意对象属性访问绕过类型检查。

阶段 2 增加 `{ "op": "variable", "variable_id": "变量 UUID" }`；变量必须在文档包中声明，不能冒充题目 ID。独立表达式入口没有变量声明环境时会拒绝该引用。

### 缺失与错误

运行值包括布尔、数字、文本、单选、多选及 `missing`。布尔位置的 `missing` 即 unknown。缺失来源包括无答案、明确 null 和被流程层排除的答案。空白文本、空多选的业务规范化由问卷层负责，原始错误输入不能默默变成缺失。

- `not unknown = unknown`。
- `false and unknown = false`，`true and unknown = unknown`。
- `true or unknown = true`，`false or unknown = unknown`。
- 普通比较、算术、长度、选择判断传播缺失。
- `answered` 仅判断规范化答案是否存在，`coalesce` 显式消除缺失。
- 布尔列表从左向右短路；编译器仍检查所有分支。运行错误不是 unknown；除零、溢出和输入类型错误必须返回结构化错误。
- 求值前统一检查所有被引用的上下文值。即使某个分支将被短路，无效上下文也不能通过；纯计算分支的运行错误只有执行到该分支时才触发。

### 数值、文本和资源界限

基础版沿用现有答案的有限 IEEE 754 binary64 数值语义，不承诺任意精度小数运算。数字常量以 JSON 字符串保留原文，按现有裸整数精度与 i64/u64 边界规则解析，防止浏览器先舍入。小数及指数按既有 f64 规则处理；正负零等价。比较为规范化数值的精确比较，不隐式添加容差；需要近似比较时由作者明确表达区间。算术每一步检查有限性，除零报错。

文本比较区分大小写、不自动 trim 或 Unicode 归一化；长度按 Unicode 标量计算。拒绝 NUL 及非 Unicode 标量输入。每个表达式最多 256 节点、最大深度 16（根为 1），文本常量最多 5000 标量，数字原文最多 64 字符（正指数补号后计）。每个选择集合最多 50 项。问卷级总规则预算在阶段 2 引入，不能把单表达式限制当成整个文档限制。

## 文档与执行语义（后续阶段约束）

1. `Document.logic` 可缺省且序列化省略；旧文档走原有单页行为，不能改变旧版幂等指纹。发布版本冻结规则与语义版本。未知版本拒绝执行。
2. 可见条件为 true 才显示；隐藏题不必填。基础 `required` 与动态条件做逻辑或，动态条件不能取消静态必填；unknown 的动态必填在最终校验时必须给出明确诊断。
3. 数据依赖图无环；流程图禁止任意回跳，所有节点有结构性出口。规则只能引用此前可获得的数据，汇合点引用某支独有答案必须显式处理缺失。显示规则不能依赖自身答案。
4. 页面只在 next 事件完成当前页校验后转换；按声明顺序选择第一个 true 分支。更高优先级条件 unknown 时阻止前进，不能落入默认分支。最后有默认出口。可检测的遮蔽/不可达规则给出诊断，不承诺证明任意表达式互斥。
5. answer_changed 事件在一次原子更新中重算依赖、可见性和路径；失去适用性的答案、错误与派生值清除。翻页不等于隐藏。仍适用的答案保留并重校验；返回已清理分支时从空答案开始。
6. previous 走当前有效历史；改答后裁剪失效历史。提交请求一旦进入不确定结果状态，冻结答案、版本和幂等键，重试相同载荷。
7. 服务端从入口按顺序执行，只让已校验且适用的答案进入上下文；不得先让路径外答案参与分支判断。到达 complete 仅代表可提交，事务成功后才是 submitted。
8. 整卷复制通过题目、选项、页面及变量的两遍 ID 映射重写引用；删除或改类型时报告影响，不静默放宽规则。
9. 统计以历史版本规则重算适用性，区分已答、适用未答、规则跳过。选项比例继续使用已答人数作分母。逻辑路径不等于实际浏览轨迹。旧版本 CSV 格式保持兼容。

## 阶段 2 契约与实施记录

2026-10-04 完成文档级编译。新增 `backend/src/logic_document.rs` 和 `frontend/src/document-logic.ts`，Rust 领域接口仍通过 `domain` 导出。`Document.logic` 缺省或 null 时序列化省略，不改变旧文档格式；草稿保存、复制校验会编译规则。

规则包包含必需的 `dsl_version`、`semantics_version`、`variables` 和 `rules` 四个字段，未知字段拒绝。变量条目包含稳定 `id`、声明 `value_type`、`expression`；规则条目包含目标 `question_id`，以及至少一个 `visible_if`、`required_if`、`validate` 布尔表达式。可选规则的 null 等价于缺省。一个题目不能重复声明规则，变量身份不能与题目、选项或其他变量冲突。

编译先绑定所有变量类型，再检查表达式与声明类型相符，最后进行确定性的拓扑排序：同一时刻就绪的变量取 UUID 最小者。变量不能有环。每个变量展开为传递的题目依赖集合，显示和必填规则必须只依赖严格前置题目；约束可以读取当前题，不能读取后续题。这也拒绝了通过多层变量隐藏的自引用和前向引用。删除变量、题目或选项，或重排题目导致引用失效时，保存明确失败，不自动清除规则。

文档最多 100 个变量、100 组题目规则；在单表达式 256 节点/16 层限制之外，全部表达式合计最多 4096 节点、262144 字节紧凑 UTF-8 JSON。变量计算结果按原生类型传给后续表达式，不转成答案 JSON 再解析。前端沿用现有无损 JSON 编解码，抽到独立 `json.ts` 供 HTTP 与纯文档复制共用；规范化的原生数字不再用显示字符串重新判断裸整数范围，避免把 `1e20` 误拒绝。

编译结果提供变量执行顺序，以及在规范化有效答案上下文上的变量值、规则表达式值。结果保留 unknown；尚不执行题目显隐、动态必填或最终提交校验，也不能据此认定访问路径。计算错误保留声明变量或题目规则的路径。

整卷复制两遍重写题目、选项、变量与规则目标引用。前端单题复制同步复制目标规则，保留外部依赖，重写直接的自身答案/选项引用；共享计算变量不克隆，仍指向原变量。复制不会改写文本常量中的 UUID 字符串。

阶段性发布限制：规则可以创建、保存、读取、复制，但带 `logic` 的草稿暂时不能发布。填写、提交与报表尚未执行规则，不能提前发布并让旧流程忽略规则；后续完整接入时才解除该限制。没有规则的问卷仍走原有发布与收集流程。
